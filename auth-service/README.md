# Hirera Auth Microservice

This service is responsible for handling all user authentication and management for the Hirera platform. It acts as a dedicated interface to AWS Cognito, providing a secure and centralized way to manage user sign-up, sign-in, confirmation, and other authentication-related tasks.

- **AWS SDK for JavaScript v3**: Used to communicate with AWS Cognito services.

### How It Works

The service exposes a set of REST endpoints that the main Hirera application can call. It encapsulates all direct communication with AWS Cognito, meaning the main application does not need to have any knowledge of the Cognito SDK or its configuration.

#### Authentication Flow

1.  **Sign-Up (`/auth/signup`)**: A user provides their details (including a unique username and email). The service creates a new user in the Cognito User Pool and sends a confirmation code to their email.
2.  **Confirmation (`/auth/confirm`)**: The user provides the confirmation code they received. The service validates this code with Cognito, confirming the user's email address.
3.  **Sign-In (`/auth/signin`)**: The user signs in with either their **username** or their **email address** and password. The service authenticates them with Cognito and, if successful, returns JWT tokens (access, refresh, and ID tokens).

#### Uniqueness & Security

The service is designed to be flexible, secure, and user-friendly:

-   **Username is Primary**: The primary, immutable identifier for a user in Cognito is their `username`, which is guaranteed to be unique.
-   **Email as an Alias**: The `email` is configured as a sign-in alias in Cognito. The service also explicitly checks to ensure no two users can register with the same email address.
-   **Robust Sign-In**: When a user tries to sign in, the service first attempts to authenticate with the provided identifier as a `username`. If that fails because the user is not found, it then performs a lookup to find a user whose `email` matches the identifier and retries the authentication with the correct `username`. This allows users to use either their username or email to log in seamlessly.
-   **Real-Time Validation**: The service provides an endpoint (`/auth/check-availability`) that allows the frontend to check if a username or email is already taken before the user submits the sign-up form.

### Setup and Installation

1.  **Prerequisites**:
    -   Ensure you have the [AWS CLI](https://aws.amazon.com/cli/) installed and configured with credentials that have permission to manage Cognito services.
    -   For Windows users, it is recommended to run shell scripts (`.sh`) in a **Git Bash** or **WSL** terminal.

2.  **Run the Setup Script**: This script creates the necessary AWS Cognito resources. It only needs to be run once. From this directory, run:
    ```bash
    bash cognito-setup.sh
    ```
    This command will create a `.env` file in this directory with your new Cognito User Pool credentials.

3.  **Install Dependencies**:
    ```bash
    npm install
    ```

4.  **Start the Service**:
    ```bash
    npm start
    ```
    The service will start on the port defined in your `.env` file (default is `3001`).

### API Endpoints

All endpoints are prefixed with the base URL of the service (e.g., `http://localhost:3001`).

#### Health Checks

-   **`GET /health`**: A basic health check to confirm the service is running.
    -   **Query Parameters**:
        -   `deep=true`: Performs a "deep" check, which verifies the connection to AWS Cognito.
    -   **Success Response (200 OK)**:
        ```json
        {
          "status": "healthy",
          "timestamp": "...",
          "dependencies": { "cognito": "healthy" }
        }
        ```
    -   **Failure Response (503 Service Unavailable)**: Indicates the service cannot connect to Cognito.

#### Authentication

-   **`POST /auth/signup`**: Registers a new user.
-   **`POST /auth/confirm`**: Confirms a user's registration with a code.
-   **`POST /auth/signin`**: Authenticates a user and returns JWT tokens.
-   **`POST /auth/resend-code`**: Resends a confirmation code to a user's email.
-   **`POST /auth/check-availability`**: Checks if a username or email is already in use.
-   **`GET /auth/user`**: Retrieves user details using a valid access token.
-   **`POST /auth/change-password`**: Allows an authenticated user to change their password.

### Environment Variables

The service is configured via the `.env` file, which is automatically generated by the `cognito-setup.sh` script.

-   `AWS_REGION`: The AWS region where the Cognito User Pool is located (e.g., `ap-southeast-2`).
-   `COGNITO_USER_POOL_ID`: The ID of the Cognito User Pool.
-   `COGNITO_CLIENT_ID`: The ID of the App Client configured for this service.
-   `COGNITO_CLIENT_SECRET`: The secret key for the App Client.
-   `PORT`: The port on which the service will run (e.g., `3001`).
-   `NODE_ENV`: The environment (`development` or `production`).

## 🚀 Quick Start

### Prerequisites
- Node.js 18+
- AWS CLI configured with appropriate permissions
- `jq` command-line JSON processor

### 1. Set Up AWS Cognito (Automated)

```bash
# Make the setup script executable
chmod +x cognito-setup.sh

# Run the setup script to create Cognito User Pool and App Client
./cognito-setup.sh
```

This will:
- Create a new Cognito User Pool with proper configuration
- Create an App Client with the correct authentication flows enabled
- Generate a `.env` file with all the necessary configuration
- Save configuration to `cognito-config.json` for reference

### 2. Install Dependencies

```bash
npm install
```

### 3. Start the Service

```bash
npm start
```

The service will run on `http://localhost:3001`

### 4. Test the Service

```bash
npm test
```

## 🧪 Manual Testing

### Health Check
```bash
curl http://localhost:3001/health
```

### Configuration Test
```bash
curl http://localhost:3001/test-config
```

### Sign Up a User
```bash
curl -X POST http://localhost:3001/auth/signup \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "TestPassword123!",
    "firstName": "Test",
    "lastName": "User"
  }'
```

### Confirm Email (after receiving verification code)
```bash
curl -X POST http://localhost:3001/auth/confirm \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "confirmationCode": "123456"
  }'
```

### Sign In
```bash
curl -X POST http://localhost:3001/auth/signin \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "TestPassword123!"
  }'
```

### Get User Info (using access token from sign in response)
```bash
curl -X GET http://localhost:3001/auth/user \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN_HERE"
```

### Resend Confirmation Code
```bash
curl -X POST http://localhost:3001/auth/resend-code \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com"
  }'
```

### Change Password (using access token)
```bash
curl -X POST http://localhost:3001/auth/change-password \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN_HERE" \
  -d '{
    "oldPassword": "TestPassword123!",
    "newPassword": "NewPassword123!"
  }'
```

## 🏗️ Integration with Main Application

### Option 1: Proxy Requests
Update your main application to proxy auth requests to this service:

```javascript
// In your Next.js API route
export async function POST(request) {
  const response = await fetch('http://localhost:3001/auth/signin', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(await request.json())
  });
  
  return Response.json(await response.json());
}
```

### Option 2: Direct Import
Import the `CognitoAuthService` class directly:

```javascript
const CognitoAuthService = require('./auth-service/cognito-auth');
const authService = new CognitoAuthService();

// Use authService.signIn(), authService.signUp(), etc.
```

### Option 3: Environment Variables
Copy the generated `.env` values to your main application's `.env.local`:

```bash
# Copy from auth-service/.env to JOBSOFT-dev/.env.local
cp auth-service/.env ../src/.env.local
```

## 🛠️ Troubleshooting

### Common Issues

**"Auth flow not enabled for this client"**
- Run the setup script again: `./cognito-setup.sh`
- Ensure the App Client has `ALLOW_USER_PASSWORD_AUTH` enabled

**"Username cannot be of email format"**
- The setup script configures this correctly
- If manually created, ensure User Pool allows email as username

**"Missing required Cognito configuration"**
- Check that `.env` file exists and has all required values
- Run `npm run test` to verify configuration

**"Connection refused"**
- Ensure the service is running: `npm start`
- Check the port is available (default: 3001)

### Manual Cognito Setup (if script fails)

If the automated setup script doesn't work, you can manually create the resources:

1. **Create User Pool:**
```bash
aws cognito-idp create-user-pool \
  --pool-name "JobTracker-UserPool" \
  --username-attributes email \
  --auto-verified-attributes email
```

2. **Create App Client:**
```bash
aws cognito-idp create-user-pool-client \
  --user-pool-id YOUR_USER_POOL_ID \
  --client-name "JobTracker-AuthService" \
  --generate-secret \
  --explicit-auth-flows ALLOW_USER_PASSWORD_AUTH ALLOW_USER_SRP_AUTH ALLOW_REFRESH_TOKEN_AUTH
```
